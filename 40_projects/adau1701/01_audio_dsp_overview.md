# 音频 DSP 的嵌入式视角

## 这个问题是什么

ADAU1701 可以作为接触音频 DSP 的入口。它把很多音频处理细节封装成可配置模块，让嵌入式开发者先从系统连接、配置下载和参数控制入手，而不是一开始就进入算法推导。

从嵌入式视角看，音频 DSP 不是一个普通外设，也不是一个通用 MCU。它更像一个专门处理实时音频流的处理器：

```text
音频输入
  -> ADC / 数字音频接口
  -> DSP 处理链路
  -> DAC / 数字音频接口
  -> 音频输出
```

MCU 的角色通常不是逐点计算音频采样，而是负责：

- 上电和复位控制。
- 通过 I2C / SPI 下载程序和参数。
- 切换音效场景。
- 调节音量、EQ、混音比例等运行参数。
- 处理按键、旋钮、通信协议和产品状态。

## 先建立的概念

- 音频是连续实时数据流，不是普通的离散命令。
- 采样率决定每秒需要处理多少个采样点。
- 音频处理链路需要稳定、低延迟、不中断。
- DSP 程序更像一张信号流图，而不是传统的主循环。
- 嵌入式主控和 DSP 之间通常是控制面与数据面的分工。

## 暂时不深入的问题

- 不从头推导 FIR / IIR 算法。
- 不一开始手写完整音频效果器。
- 不把重点放在浮点、定点和系数量化细节上。

这些问题后续可以逐步补，但第一阶段先把音频系统跑起来、调起来、听得出变化。






# mcu 与 dsp

## 音频链路

ADAU1701 是一个专用音频 DSP。音频信号进入芯片后，由它内部的 DSP 程序处理，比如 mute、volume、EQ、滤波、混音，然后再从输出端出来。

ESP32 通常不参与音频实时运算，也不是通过 I2C 把音频一帧帧送进去。I2C 只是控制通道，用来下载 DSP 程序、改音量、改 EQ、静音等。


```md
音频输入 -> ADAU1701 DSP算法处理 -> 音频输出
              ^
              |
          ESP32 通过 I2C 配置/控制
```


## 控制链路


ADAU1701 上电后只是一个空的 DSP 核心，需要有一套 SigmaStudio 生成的程序和参数。这个项目里是 ESP32 通过 I2C 把程序下载进去。

当前项目启动流程大概是：

```md
ESP32启动
  -> 加载DSP固件数据
  -> 初始化 GPIO / I2C
  -> 找到 ADAU1701 I2C 地址
  -> 下载 Program RAM
  -> 下载 Parameter RAM
  -> 写硬件配置
  -> 启动 DSP Core
  -> 后续通过 Safeload 改音量/静音/EQ
```

一些概念：
- Program Data， SigmaStudio 里画出来的音频处理流程编译后的 DSP 指令。
- Parameter Data，模块的参数，比如音量值、mute 开关、EQ 系数、滤波器系数。
- SigmaStudio 工程，固件数据来源
- Safeload，DSP 正在跑的时候，如果直接改参数 RAM，可能产生爆音或不稳定。Safeload 是 ADAU1701 提供的安全更新参数机制。
