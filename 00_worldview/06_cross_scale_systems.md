# 从电路到社会：一个跨尺度系统观

如果只看目录，我的这些笔记像是分散在几个仓库里：

- `electronics`：电子学、电路、电机控制。
- `control-theory`：控制理论、数学、机器人系统。
- `embedded-system`：计算机、嵌入式、操作系统、Linux、Agent。
- `cyberlosophy`：认知心理学、管理学、社会与哲学。

但如果从系统的角度看，它们并不是完全分散的。

它们都在反复处理一些相似的问题：

- 状态如何表示？
- 信息如何流动？
- 能量或资源如何分配？
- 目标如何设定？
- 控制如何建立？
- 反馈如何形成？
- 系统边界在哪里？
- 复杂性如何被管理？
- 理论如何进入现实？

这篇文章尝试把这些内容放到一张更大的图里。

## 1. 电路系统：信号与能量

电子电路是最靠近物理世界的一层。

在这一层，系统面对的不是抽象变量，而是电压、电流、阻抗、频率、噪声、功率、热、器件非理想性。

电路分析建立的是对“电”的基本直觉。模拟电路处理信号放大、滤波、反馈、稳定性。数字电路把复杂连续的电信号封装成高低电平、逻辑门和状态机。电力电子和电机控制进一步进入功率变换和执行器控制。

所以 `electronics` 不是单纯的“电路课笔记”，它在整个系统观里扮演的是：

```text
真实物理世界和计算控制系统之间的接口层
```

它回答的问题是：

- 现实世界的物理量如何变成电信号？
- 电信号如何被放大、滤波、比较、转换？
- 连续信号如何进入数字系统？
- 数字控制量如何变成电压、电流和功率输出？
- 电机如何把电能变成机械运动？

传感器、ADC、DAC、PWM、驱动电路、电机，这些都不是边角料，而是“系统能否作用于现实世界”的关键。

没有电子电路，计算机只能在自己的符号世界里运行；有了电子和执行器，计算才真正能进入物理世界。

## 2. 计算系统：状态与程序

计算系统把世界进一步抽象成状态和状态迁移。

数字电路已经是状态机，CPU 也是状态机，程序还是状态机。C 语言、汇编、ELF、链接、加载、系统调用，本质上都围绕一个问题：

```text
人的意图如何变成机器可执行的状态迁移？
```

嵌入式系统让这个问题更具体。一个程序不只是输出字符，而是要读传感器、处理中断、调度任务、访问设备、驱动电机、连接网络。

因此 `embedded-system` 在整个系统观里扮演的是：

```text
计算如何被组织起来，并进入具体工程对象
```

它回答的问题是：

- 状态如何被编码和存储？
- 程序如何被编译和加载？
- 控制权如何从 reset 流向 firmware、bootloader、kernel、init、application？
- 操作系统如何把硬件资源抽象成对象和 API？
- RTOS 和 Linux 如何管理任务、设备、内存和时间？
- 工具链、构建系统、调试器如何让系统可观察、可修改？

从这个角度看，计算机不是一个独立学科孤岛，而是现代工程系统的中枢神经。

## 3. 控制系统：目标与反馈

有了信号和计算，还不等于系统能按目标工作。

控制系统关心的是：如何让系统状态朝目标变化，并在扰动、不确定性和现实约束下保持可接受的性能。

控制理论的关键词是模型、反馈、稳定性、鲁棒性、能控性、能观性、优化、约束。

但我越来越觉得，控制理论最重要的不是某个具体算法，而是一种系统调控视角：

```text
理解系统特色，在目标、模型、反馈和约束之间建立可验证的调控方式。
```

`control-theory` 里关于模型与实际、系统特色、理论和工程差距的讨论，比单纯公式更重要。

里面有几个核心判断：

- 模型不是现实本身，而是为了控制目标而建立的近似。
- 模型不准不是问题的全部，关键是哪些误差会影响目标。
- 数据驱动和模型驱动不是敌人，都是理解和近似系统的路线。
- 控制方法有没有价值，取决于是否抓住系统特色。
- 控制理论不能只在路灯下找钥匙，必须回到真实需求。
- 理论学家和工程师需要见面，否则论文和现场会跑成两条线。

这个判断可以推广到很多领域：

**一个理论能不能成为工程能力，不取决于它在纸面上多漂亮，而取决于它是否抓住了系统真实约束。**

## 4. 工程系统：约束与落地

工程系统是计算、控制、电子、电机、软件、工具、人和组织的综合体。

工程里的困难往往不在单个公式，也不在单个 API，而在链路太长：

```text
传感器
-> 信号调理
-> ADC
-> MCU / Linux
-> 驱动
-> 任务调度
-> 控制算法
-> PWM / 总线命令
-> 功率驱动
-> 电机 / 执行器
-> 机械结构
-> 新的传感器反馈
```

任何一环不可靠，最后都可能表现为“系统不好用”。

所以工程系统的核心不是堆知识，而是管理约束：

- 成本；
- 功耗；
- 实时性；
- 安全；
- 可靠性；
- 可维护性；
- 调试能力；
- 团队协作；
- 交付周期。

这也是为什么“最小可运行系统”很重要。完整走通一个小系统，可以先建立全链路直觉，再把它映射到复杂系统。

## 5. 认知系统：信息与决策

`cyberlosophy` 里的认知心理学看似离工程很远，但其实它回答了另一个层级的问题：

```text
人如何获得、储存、转换、运用和沟通信息？
```

这和计算系统有相似处，但对象变成了人。

人也有输入、注意、记忆、模式识别、推理、问题解决和决策。只是人的系统不是确定性的机器程序，而是受经验、情绪、动机、环境和认知限制影响的复杂系统。

认知心理学对技术世界观的意义在于：

- 学习不是把知识塞进脑子，而是建立可调用的表征结构。
- 注意力是稀缺资源，和计算系统里的内存、上下文窗口有某种类比。
- 决策不是纯理性优化，而是受信息可得性、认知偏差和环境反馈影响。
- 工具会改变人的认知能力边界。

这也能解释为什么 AI Agent 时代，“问出好问题”变得很重要。模型能力很强，但人的任务表达、问题分解、验证判断仍然决定系统最终效果。

## 6. 组织系统：协调与管理

管理学可以理解为更高一层的控制问题，但对象不是电机、程序或设备，而是人和组织。

组织有目标，有资源，有任务，有角色，有边界，也有反馈。

管理者做的事情，某种意义上和系统架构师类似：

- 设定目标；
- 分解任务；
- 配置资源；
- 协调人；
- 建立流程；
- 观察反馈；
- 修正方向；
- 处理冲突和不确定性。

但这里必须小心：人不是机器，组织也不是简单控制系统。

人有主观性、价值判断、动机、情绪、利益和尊严。组织系统中，目标本身可能会被争论，指标可能会扭曲行为，反馈可能会失真，资源分配会涉及权力关系。

所以管理学不能被粗暴还原成控制理论。

更合理的说法是：

```text
系统视角可以帮助理解组织，但不能取消人的主体性。
```

这也是从工程系统走向社会系统时必须保留的边界感。

## 7. 社会系统：历史与实践

`cyberlosophy` 里的马克思主义、社会和历史部分，可以放在更大的尺度上看。

它关心的问题不再是某个设备如何稳定运行，而是：

- 社会结构如何形成？
- 生产关系如何影响人？
- 历史事件如何在条件中展开？
- 理论如何在实践中发展？
- 组织如何设定目标并动员资源？
- 个人如何理解自己和时代的关系？

这些问题不能像电路那样直接列方程，也不能像程序那样单步调试。

但其中仍然有一些和工程系统相通的方法：

- 从现实问题出发，而不是从空洞概念出发；
- 看结构，不只看孤立个体；
- 看历史条件，不只看静态结论；
- 看实践反馈，不只看理论宣称；
- 把大任务拆成小任务，把长期目标落到具体行动。

你在这些材料里写到“马克思主义是一种世界观、方法论”，以及“理论在实践中发展”，这和工程里的一个判断是相通的：

**理论不是离开现实自转的东西，它要在现实中被检验、修正和发展。**

## 8. Agent 系统：意图与工具

AI Agent 是这张跨尺度地图里的新层。

传统计算系统里，人通过代码表达意图。Agent 系统里，人开始通过自然语言、文档、任务、约束和反馈表达意图。

```text
人的意图
-> 自然语言任务
-> LLM
-> Harness
-> Tool / Code / Shell / Git / MCP
-> 工程结果
```

这让 Agent 处在一个很特别的位置：它既是计算系统，又像认知工具；既调用工程工具，又参与组织协作；既能写代码，又需要被规则和反馈约束。

所以 Agent OS 可以被看作一种新的系统层：

- LLM 提供语言和推理能力；
- Harness 提供工具、状态、权限、环境和反馈；
- MCP 提供外部能力连接；
- Skill/Command 提供可复用流程；
- Hooks 提供确定性约束；
- Subagent/Agent Team 提供任务分工；
- 仓库提供系统记录。

它把“人的意图如何进入工程系统”这件事推到了前台。

## 9. 跨尺度地图

这些领域可以粗略排成一张图：

```text
物理系统
  电路、信号、能量、器件非理想性

计算系统
  状态、程序、指令、操作系统、工具链

控制系统
  目标、模型、反馈、稳定性、鲁棒性

工程系统
  约束、成本、可靠性、调试、交付

认知系统
  注意、记忆、学习、推理、决策

组织系统
  目标、协作、资源、管理、反馈

社会系统
  历史、结构、实践、制度、价值

Agent 系统
  意图、上下文、工具、权限、反馈、自动化
```

这不是说所有系统都能用同一套公式统一。

恰恰相反，尺度越往上，人的主观性、价值冲突、历史条件和不确定性越强，越不能简单机械化。

但这张图能帮助我意识到：不同学科里反复出现了一些相似的问题结构。

## 10. 一个共同问题

如果把这些学科继续压缩，它们都在问一个共同问题：

```text
如何在复杂世界中建立可理解、可行动、可反馈、可演化的系统？
```

电子电路让物理世界变成信号，并把信号变成功率输出。

计算机让状态迁移可编程。

控制理论让系统变化服从目标。

嵌入式工程把计算和控制落到真实对象上。

认知心理学帮助理解人如何处理信息。

管理学研究组织如何协调行动。

社会理论研究更大尺度的结构、实践和历史演化。

Agent OS 则试图让自然语言意图进入工程自动化系统。

这些东西并不是一门“统一理论”，但它们共同构成了我理解技术世界的坐标系。

## 11. 边界感

最后必须补一句边界。

系统视角很有用，但也危险。

它容易让人产生一种错觉：只要能画框图、列变量、设计反馈，就能理解和控制一切。

这在电路和嵌入式系统里已经不总是成立，在人和社会系统里更不成立。

人不是传递函数，组织不是简单状态机，社会也不是可以随意调参的控制对象。

跨尺度系统观的价值，不是把所有东西机械化，而是提醒自己：

- 面对复杂对象时，先看结构和边界；
- 面对行动目标时，建立反馈；
- 面对理论时，回到现实约束；
- 面对人和社会时，保留价值、历史和主体性。

所以这套世界观最终不是为了“控制一切”，而是为了更清楚地理解：

**在不同尺度上，系统如何形成、如何运行、如何失效，以及人应该如何谨慎地参与其中。**
