```md
# 个人 Codex 工作区方案

## Summary
建立一个轻量中文 Markdown 工作区，让 Codex 作为「执行助理」管理个人任务、项目状态、每日整理和周复盘。工作区以「项目 + 今日」为主视图，避免复杂系统，优先保证每天能快速更新、Codex 能快速读懂当前状态。

## Key Changes
- 创建固定入口：
  - `README.md`：工作区说明和快速导航。
  - `AGENTS.md`：给 Codex 的工作规则，例如先读入口文件、维护任务状态、不要覆盖用户记录。
  - `00_入口/今日.md`：当天重点、下一步、等待事项。
  - `00_入口/收件箱.md`：临时想法、待整理事项。
  - `00_入口/本周.md`：本周目标、项目进展、风险和复盘。
- 创建工作目录：
  - `10_项目/`：每个项目一个 Markdown 文件，记录目标、当前状态、下一步、决策和阻塞。
  - `20_记录/每日/`：每日工作日志。
  - `20_记录/周复盘/`：每周复盘。
  - `30_资料/`：长期参考资料、流程、联系人或背景信息。
  - `90_归档/`：完成或暂停的项目与历史资料。
- 创建模板：
  - 项目模板：目标、成功标准、当前状态、下一步、等待中、记录。
  - 每日模板：今日重点、完成、遇到的问题、明日下一步。
  - 周复盘模板：本周完成、未完成、阻塞、下周计划。
- 建立 Codex 使用方式：
  - 每次开始工作时，Codex 先读 `00_入口/今日.md`、`00_入口/本周.md` 和相关项目文件。
  - 用户可以用自然语言说「整理今天」「更新项目 X」「做周复盘」「列出下一步」，Codex 按模板维护文件。
  - 任务状态统一使用：`未开始`、`进行中`、`等待中`、`已完成`、`已归档`。

## Test Plan
- 检查目录和模板是否完整，且所有入口文件互相链接。
- 用一个示例项目验证 Codex 能从 `今日.md` 找到项目、更新下一步、沉淀到项目文件。
- 验证 `README.md` 能让新会话快速理解工作区用途。
- 验证 `AGENTS.md` 的规则足够明确，避免 Codex 修改无关文件或丢失人工记录。

## Assumptions
- 使用中文文件名和中文模板。
- 不接入日历、邮件或外部任务系统，先做本地 Markdown 工作区。
- 保留当前 git 仓库，不重置已有内容；`README.md` 当前已有未提交修改，实施时只在确认内容后更新。
- 采用轻量结构，不引入数据库、自动化脚本或复杂看板。

```
