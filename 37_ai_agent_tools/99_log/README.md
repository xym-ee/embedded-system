最基本的用法。启动以后，总结项目，修改一些功能。

之后需要了解一些 LLM 的基本原理，基本概念，context windows，压缩，agent loop 。好多机制都是为了解决 LLM 本身的限制设计的。

再去试着搞一些中等规模的 claude codex，中型项目，AGENTS.md ，长期做的任务，隐形知识全都显示的给到 AI。
- 如个人任务管理(claude 试着 模拟openclaw hermes记忆， 手动维护的长期记忆机制)


对于代码项目，源码，记忆？差不多，但有区别，更严格的语法约束，依赖关系，耦合关系，。

两套东西，源码本身，给 ai 看的源码的说明。

claude 向外扩张，除了文本，还想做点其他事情。例子，日报生成，视频总结为 pdf 笔记。

手动做的，模块化，任然是软件工程的思路。封装，

SKILL.md ，md 本身是说明书，但是 skill 包含了资源和工具，自然语言解决语义匹配，确定性的过程用脚本完成。如 ai 生成日报，用 latex 模板解决排版样式生成不确定性的问题，AI 只做其擅长的概念解释，总结等，生成文字，样式又确定的代码负责。


目前觉得比较合适的路线
- 一次性任务：总结项目、改小 bug、写脚本。
- LLM 基础：上下文、幻觉、token、压缩、工具调用、agent loop。
- 项目上下文工程：README、AGENTS.md、架构说明、测试说明、任务日志。
- 中长期任务：拆任务、保留决策、维护记忆、复盘失败。
- 技能化/模块化：SKILL.md、模板、脚本、资源文件、自动校验。
- 稳定化：测试、评估、安全、权限、日志、回滚。
